| Field | Value |

## 1. System overview

PosingInCam is a deterministic batch image generator. There is no runtime, no server, no database. The user runs a CLI; the CLI reads a pose library, renders JPEGs sized and named for a target camera, and writes them to a directory the user copies to an SD card.

```
                    ┌──────────────────────────────────────────────┐
                    │              posingincam CLI                 │
                    │                                              │
poses/*.yaml ──────►│  ┌────────┐   ┌────────┐   ┌────────────┐    │
                    │  │ loader │──►│ render │──►│ writer     │    │
camera profile ────►│  └────────┘   └────────┘   └────────────┘    │
(YAML)              │       │           │              │           │
                    │       ▼           ▼              ▼           │
                    │   schema      SVG → PNG     EXIF + DCF       │
                    │   validation  → JPEG        folder layout    │
                    └───────┬──────────────────────────────────┬───┘
                            │                                  │
                            ▼                                  ▼
                       (errors)                          dist/<camera>/DCIM/...
                                                          │
                                                          ▼  user copies
                                                       SD card
                                                          │
                                                          ▼ user inserts
                                                       Camera ─► playback
```

## 2. Technology choices

| Concern | Choice | Why |
| --- | --- | --- |
| Language | Python 3.11+ | Best image-processing ecosystem (Pillow, piexif), low contributor barrier, fast iteration. |
| CLI framework | Typer | Type-driven, great UX, autogenerated help. |
| Pose source format | YAML | Multiline strings for the verbal cue, comments, human-friendly diffs. |
| Schema validation | Pydantic v2 | Same models drive validation and runtime types. |
| SVG composition | Jinja2-templated SVG | Layout is declarative; designers edit templates not code. |
| SVG → raster | `cairosvg` (preferred) or `resvg` via `python-resvg` | Both render SVG faithfully; resvg is faster, cairosvg is more compatible. Pick after benchmarking in M1. |
| Raster → JPEG | Pillow with `mozjpeg` encoder if available | Smaller files at same quality. |
| EXIF write | `piexif` | Mature, supports the tags we need (Make, Model, ImageDescription, ThumbnailImage). |
| Tests | pytest + golden-image diffing (`pixelmatch-py` or perceptual hash) | Catches accidental visual regressions without false positives on JPEG artifact noise. |
| Linting | ruff + mypy | Standard Python toolchain. |
| Packaging | `hatch` / `pyproject.toml` | Modern, no setup.py. |
| CI | GitHub Actions | Free, integrated, matrix builds. |

### Rejected alternatives

- **Node + sharp**: faster JPEG encoding, but YAML→Pydantic workflow and pose contributor experience is much weaker in TS.
- **Rust**: overkill; rebuild times and contributor barrier dominate any perf win.
- **Headless Chromium for rendering**: heavy, non-deterministic across versions, slow.
- **Static PDF as intermediate**: doesn't compose well with EXIF embedding and adds a step that buys nothing.

## 3. Data model

### 3.1 Pose (YAML, one per file)

```yaml
# poses/forehead-touch-walking-in.yaml
id: P-042
slug: forehead-touch-walking-in
title: Forehead Touch — Walking In
pack: essential
difficulty: 1                    # 1=easy, 2=medium, 3=advanced
tags: [intimate, walking, golden-hour]
illustration: illustrations/forehead-touch-walking-in.svg
positioning:
  her:
    - Walk slightly ahead, body angled 30° toward him.
    - Lead hand brushes his at hip height.
    - Chin slightly down, eyes up.
  him:
    - Match her pace, half a step behind.
    - Free hand at his side, relaxed.
    - Angle his forehead in to meet hers on the third step.
camera_notes:
  lens: 35mm or 50mm prime
  aperture: f/1.8 – f/2.8
  angle: Eye level, slight low.
  distance: 8–12 ft, lead the walk.
  notes: Burst at 5–7 fps; the moment is the contact, not the approach.
verbal_cue: |
  "Walk toward me holding hands.
   When you're three steps out, lean in
   and touch foreheads — keep walking."
variations:
  - Stop on contact instead of walking through.
  - Add a laugh prompt: "Now whisper something dumb."
authored_by: TBD
art_credit: TBD
version: 1
```

### 3.2 Camera profile (YAML, one per camera)

```yaml
# src/posingincam/cameras/profiles/sony-a7iv.yaml
id: sony-a7iv
display_name: Sony Alpha 7 IV
manufacturer: Sony
dcf:
  folder_number: 199               # default; user-overridable
  folder_tag: MSDCF                # 5-char DCF tag
  file_prefix: DSC0                # 4-char DCF prefix
  starting_index: 1                # files start at DSC00001.JPG
image:
  width: 3840
  height: 2560
  jpeg_quality: 85
  color_space: sRGB
exif:
  make: SONY
  model: ILCE-7M4
  software: posingincam/0.1
  date_time_original: "2000:01:01 00:00:01"
  spoof_make_model: true           # spoof to maximize playback compatibility
notes: |
  Tested on firmware 3.01. Cards display in playback grid view
  with line-art thumbnail. Zoom works to 100%.
```

## 5. Render pipeline

```
Pose YAML
   │
   │  pose.loader.load(path) → Pose (Pydantic)
   ▼
Camera profile YAML
   │
   │  cameras.registry.get("sony-a7iv") → CameraProfile
   ▼
Layout
   │
   │  render.layout.render(pose, profile)
   │     - pick template (default | landscape | square)
   │     - bind variables into Jinja2 SVG template
   │     - inline the illustration SVG
   │  → SVG string
   ▼
Rasterize
   │
   │  render.rasterize.svg_to_png(svg, profile.image.width, .height)
   │  → PIL.Image (RGBA)
   ▼
Compose JPEG
   │
   │  render.jpeg.encode(image, profile) → bytes
   ▼
Generate thumbnail
   │
   │  render.thumbnail.from_illustration(pose, 160, 120) → JPEG bytes
   ▼
Embed EXIF + thumbnail
   │
   │  render.exif.embed(jpeg_bytes, thumbnail_bytes, profile, pose)
   ▼
Final JPEG bytes
   │
   │  output.writer.write(bytes, dcf_path)
   ▼
dist/<camera>/DCIM/199POSEX/DSC00042.JPG
```

## 7. DCF compliance details

The Design rule for Camera File system (JEITA CP-3461) is the standard cameras follow when reading SD cards. Our output must respect it or playback won't recognize files.

### Folder

- Path: `DCIM/NNNXXXXX/` where:
  - `NNN` = three-digit folder number, **100–999**.
  - `XXXXX` = five uppercase alphanumeric characters (no spaces, no symbols).
- Examples: `100MSDCF` (Sony), `100CANON` (Canon), `100NCD850` (Nikon D850 era), `100_FUJI` (Fujifilm uses underscores — these are still in the allowed set).
- We default to folder number **199** to land far above users' active counters but below 999, and we expose `--folder-number` for collision avoidance.

### File

- Filename: `XXXXNNNN.JPG` where:
  - `XXXX` = four uppercase alphanumeric characters (vendor convention).
  - `NNNN` = four-digit sequence, **0001–9999**.
- We use the camera profile's `file_prefix` as `XXXX` and number sequentially from `starting_index`.
- Files within one folder share a common `XXXX`. Crossing 9999 requires a new folder.

### Image content

- Must be valid baseline JPEG (we use Pillow's default; no progressive).
- Must include EXIF APP1 segment with at least Make, Model, Orientation.
- Embedded thumbnail in EXIF IFD1, JPEG-compressed, **160×120** for max compatibility.
- sRGB color space.

### Filesystem

- SD card formatted FAT32 or exFAT (camera's choice). We don't format; we copy.
- Filenames uppercase. (Some camera firmwares are case-sensitive.)

## 8. Determinism

Re-running `build` on unchanged inputs must produce byte-identical outputs. This makes diffs reviewable, lets us cache, and supports reproducible-build claims.

- **Sort everything**: pose discovery sorts by id, dict serialization sorts keys.
- **Freeze timestamps**: `DateTimeOriginal` and `DateTimeDigitized` come from the pose `version` (or a fixed epoch), never from `now()`.
- **Pin dependencies**: `requirements.lock` with hashes.
- **Deterministic SVG → PNG**: cairosvg/resvg are deterministic given the same input and version.
- **JPEG encoder version pinning**: pin Pillow + libjpeg-turbo via the lockfile.
- **CI check**: a job that builds twice and diffs outputs.

## 9. Testing strategy

| Layer | Tooling | What it checks |
| --- | --- | --- |
| Unit | pytest | Pose loader, schema validation, DCF naming logic, EXIF writer. |
| Golden | pytest + perceptual hash diff | Each pose × each profile renders to a known-good image (within tolerance). Updated via `pytest --update-golden`. |
| Integration | pytest with tmp_path | Full `build` of a tiny pose set produces a valid DCF tree. |
| DCF compliance | custom validator (`tests/dcf_validator.py`) | Walks output, asserts folder/file naming, EXIF presence, thumbnail validity. |
| Camera-in-the-loop | manual + `docs/CAMERA_TEST_PROTOCOL.md` | A maintainer runs the protocol against real hardware before adding a Tier 1 profile. Results recorded in `docs/CAMERA_TEST_RESULTS.md`. |
| CI | GitHub Actions matrix | macOS, Ubuntu, Windows × Python 3.11, 3.12, 3.13. |

## 10. Performance budget

| Operation | Target | Stretch |
| --- | --- | --- |
| Single card render (SVG → JPEG with EXIF) | ≤ 1 s | ≤ 300 ms |
| Full library (100 poses) for one camera | ≤ 60 s | ≤ 15 s |
| Full library × 6 Tier 1 profiles | ≤ 4 min | ≤ 90 s |

Parallelism via `concurrent.futures.ProcessPoolExecutor` (the rasterize step is CPU-bound and embarrassingly parallel).

## 11. Distribution

- **PyPI**: `pip install posingincam`.
- **Pre-built bundles** (M5+): GitHub Releases attach `posingincam-library-sony-a7iv-v1.0.zip` style artifacts so non-Python users can just download and copy. Built by CI on tag.
- **Single-binary** (M6+): PyInstaller / shiv bundle for Windows/macOS users who don't want Python.

## 12. Security and safety

- No network calls at runtime.
- `install` command requires the target path to look like a removable/external mount; refuses to write to system paths without `--force`.
- Refuses to write into a `DCIM` folder that already has files unless `--merge` or `--overwrite` is passed.
- `doctor` command summarizes what `install` will do (dry-run by default).
